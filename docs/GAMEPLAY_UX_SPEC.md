# ゲーム進行・画面UX・チュートリアル仕様 v0.1
更新: 2026-10-22 / ゲームの「遊べる」完成条件を明文化する。

## 1. プレイヤー体験・勝敗
- ファンタジー: 自分のコンビニを、狭い空店舗から使いやすく利益の出る売場に育てる。
- 1ゲーム日のループ: 配置→仕入→補充→広告予算→営業→客行動→日次決算→改善。
- MVPは**自由経営型（Sandbox）＋チュートリアル目標**。ゲームオーバー強制はしない。日次目標を達成すると店舗評価が上がる（目標リストと実績が可視化）。
- 成長軸: 商品種類・棚容量・利益・来店客数・満足度。土地拡張や新什器解禁、従業員管理はMVP後。
- 初期資金は**仮50万円**、初期レジ0、入口2タイル、棚0、在庫0。最低1台のレジ/1台の棚/補充済商品が揃わないと「営業開始」できない。
- 初期設備/価格/広告値はバランス仮値。チュートリアルが開始資金内で達成可能でなければゲームとして失敗。
- 固定費などが払えない場合は支払不能状態で時間停止。**破産で即終了はしない**。チュートリアル再開/前日のセーブ復元/新規ゲーム案内。救済機能はリリース前に検証。

## 2. 初回5分の導線（MVP）
1. 新規ゲーム→空店舗を表示、所持金と日付、操作ヒント。
2. 「レジを置く」をガイド。タイルプレビュー、回転R、設置費用を確認。
3. 「飲料冷蔵ケース（または汎用棚）を設置」。アクセス面に通路があることを教える。
4. 「飲料を10個仕入れる」。仕入により現金とバックヤードが変化。
5. 「棚へ補充」。棚在庫とスプライトの見た目が更新。
6. 「営業開始」。客が入店→棚へ歩く→レジ→会計→退出。
7. 1日目を終了、売上/粗利/現金/来店客数を表示。
8. 「広告を翌日分だけ設定」、集客が改善するか観察する。
- ガイドはスキップ/再表示可能。目標の進行状況は**実際のゲーム状態**から判定し、UIクリック履歴だけで達成と見なさない。
- 什器が高額すぎてチュートリアルが完了できないときはバランスデータ側を修正。無料で配る裏仕様にしない。

## 3. 画面の情報設計
### 上HUD
- 所持現金（通貨記号と桁区切り）、ゲーム内日付/時刻、速度、営業状態、当日売上高、当日粗利、実来店客数、低在庫件数。
- ツールチップで定義（粗利は売上−売上原価、現金とは違うことを説明）。未確定/無効は「—」。

### 左パレット
- カテゴリ（レジ/一般棚/冷蔵・冷凍/温食品/構造/装飾）、カードにアセット絵/名前/寸法/価格を表示。
- クリックまたはドラッグでプレビュー、Rで回転、左クリック設置、Esc/右クリック解除。選択を変えたら以前のプレビューを消す。
- コントロール上ドラッグが店舗パンや配置操作に伝播しない。

### 右インスペクタ
- 選択什器の名前・寸法・向き・対応カテゴリ・販売アクセス面・棚容量/現在陳列数量/取り置き数・当日売上・補充・移動・撤去。
- SKUリストは名前、価格、在庫、期限間近表示。存在しない棚や未選択時には空状態/説明を表示。
- 自由なレジ/棚配置が不可能な理由を「場所」「在庫」「資金」「営業状態」のどれが原因か示す。

### 経営タブ
- 仕入れ/商品価格/広告/日次レポート/保存。収支タブは「損益」と「現金」を分離。
- 広告は今日の適用予算と翌日予約予算を並べて表示。「翌日適用」を明記。
- 日次レポートの推移は売上/粗利/廃棄/広告/現金。グラフ無しでも数値表で確認可能。

## 4. 操作状態機械
- `observe`（通常選択）、`place`（設置）、`move`（移動）、`inspect`（詳細操作）、`modal`（仕入等ダイアログ）は**排他的な入力モード**。
- UIのクリック/ドラッグがワールドに伝播しない。選択・パン・配置を1イベントで同時発火させない。
- 配置プレビューは合法(○)、不可能(×)、注意(!)をグリッド色と文言で表す。重複・屋外・入口妨害・資金不足・閉店中のみ操作可能など理由を別テキストに。
- 建設は**SETUP時にのみ可能（ゲーム時計は停止）**。OPEN+時計一時停止では建設モードに切り替えない。客がいる間は明示的閉店後も建設不可、店内客/予約が0になったSETUPで編集可能。
- Back/Cancelで操作をすべて無変更で中止。設備設置の購入確定には確認が必要（低価格設備はオプションで省略可、ただしUndoの返金規則は統一）。
- Undo/Redoは停止中のレイアウト編集のみ。すでに営業した/仕入れた/客が購入した経営イベントの巻き戻しは行わない。

## 5. 店舗ビューの使いやすさ
- 1920×1080基準、余白のあるHUD。小画面では左右パネルを折り畳め、中央ビューの操作面積を確保。
- ズーム0.5〜2.0、マウス位置を基準にズーム。Space+左ドラッグまたは中ドラッグでパン。全体表示（Fキーなど）を追加。
- 背の高い棚で見えない手前/奥のセルや客を見分けるため、ホバー・選択時の輪郭表示と前景什器の一時半透明化を定義。
- リアル寄りでも棚の種別は看板・値札・画面UIで識別。赤緑だけで設置可否を表現しない。
- ゲーム内速度、ボリューム、画面スケール、操作ヘルプへのアクセスを確保。
- 最低限の日本語UIを採用し、文字長増加・折り返しに耐える。英語翻訳はMVP後。

## 6. データからの達成判定
- 「最初の棚を設置」: 有効なfixture instanceが存在。
- 「初回補充」: 互換カテゴリの棚stock qtyが1以上。
- 「初回売上」: SalesTransactionが1件以上確定済み。
- 「日次黒字」: 日次簡易営業損益が正（設備購入支出とは分離）。
- 「広告実験」: 翌日予算を設定しその日の記録に適用された。
- 目標結果と次の行動を明示。未達成時はなぜ達成できないかを表示。

## 7. 各画面のQAシナリオ
- UIパネルが店舗操作をブロックし、背後タイルに設置しない。
- 什器を置いても店内経路が途切れない/途切れる場合は説明される。
- 商品在庫0で棚を選択してもエラーなく空状態表示。
- レジ無し/客無し/資金不足/満員/広告効果無し/日次売上0でもレポートは破綻しない。
- キャンセル・ESC・再開・速度切替・セーブで資金や予約在庫を二重更新しない。
- グリッド/商品/客/レジが重なった場面でも該当什器へクリック選択できる。
