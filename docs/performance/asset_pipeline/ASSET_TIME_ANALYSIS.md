# 2Dアセット制作時間分析

調査日: 2026-10-28 (JST)  
対象: PR #160 (屋外連続2D景観)、PR #161 / Issue #157 (棚＋商品一体画像)

## 結論

現在の証跡だけで「制作全体で最も時間がかかる工程」は断定できない。計測できた個別イベントでは、画像生成呼び出しの **539.341秒** が最長。ただし他の候補の画像生成呼び出しは概ね28–52秒で、ケースCには生成所要時間がない。画像生成、検査、手戻り、Godot統合、レビュー、統合作業の累積時間が揃っていないため、これを工程別総時間TOP1とは呼べない。

屋外ケースは生成イベント時間と一部プロセス時間を回収できた。棚ケースは試行回数・失敗理由・修正履歴が詳しい一方、生成・加工・QAの開始終了時刻がない。ケース比較の「採用可能な完成物1件あたり時間」はいずれも算出不能。さらに最新の#157 P0 STOP（2026-10-28 06:23 JST）は屋根付き常温棚をHard FAILとし、量産を停止して新しい開放型EMPTY→FULL/r0を要求している。過去の棚成果は時間分析用の履歴であり、品質的な採用成果ではない。

## 証拠の区分

- **計測**: セッションのImageGen generation eventの明示的`started_at_ms` / `completed_at_ms`差、またはコマンド実行の記録duration。
- **履歴のみ**: Git commit時刻、PRコメント、manifestのattempt数、QA結果。作業時間ではない。
- **不明**: 端点記録がない時間。commit間隔・ファイル時刻から補完しない。

### Cの履歴量（完全な累積回数ではない）

PR #161に記録された一部の試行: general state v3 3画像、snack関連2画像＋失敗画像補正、noodle shallow v1–v5、onigiri v4–v5、model_swap (general 4 / noodle 4 / bread 2 / snack 5 / drink 2 / dessert 3 call)。一部attemptのraw画像やmanifestはPRに欠落。従って「総ImageGen呼出回数」「失敗率」は分母が確定できない。

最新P0 STOPより前の試作で、同一状態セットは独立QA FAIL。model_swapや屋根付き構造への高いIoUは、誤った屋根付き参照に対する一致度である。新しい開放型構造の形状承認が先で、過去候補を高速な完成アセットと数えない。

## 比較の結論

- A/Bは試作を進める上で、画像生成だけより投影合わせ・shader/placement修正・Godotでの再撮影に手戻りがあることを示す。ただし各所要時間が欠け、どの修正が最大コストか数値順位は作れない。
- Cは構造参照とプロンプトの誤りが反復生成を引き起こしたことをQA履歴から確認できる。これは「生成モデル待ちが遅い」とは別の品質起因リワークだが、所要時間は未計測。
- 品質ゲートを下げずに短縮する最初の手段は、generation前の参照/形状/prompt lint、生成直後の投影QA、候補出力の保存場所を明示すること。短縮効果は今後測定する。
