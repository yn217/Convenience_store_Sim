# 客が棚をすり抜けて見える問題の原因調査（#15 #23 #26）

対象: `feature/m8-customer-paths`。試験は `tests/scenario/test_customer_paths.gd`（固定seed、実シミュレーション）。

## 結論

見えていた「棚の中を歩く」は **表示側の原因（上記の原因(2)）が実在**し、修正した。論理経路（原因(1)）は今の仕様では棚を通っていなかった。描画順（原因(3)）も問題は出なかった。

| 候補 | 判定 | 根拠 |
|---|---|---|
| (1) 論理経路が棚のセルを通る | **通らない**（現仕様では到達不能） | 1.5ゲーム時間・購入71件・選択168回で、(a) 棚セル上の停止/経路 0件、(b) 斜め移動 0件、(d) 購入時の停止が正面のアクセスタイル外 0件。経路キャッシュは `grid` の同一性と `revision` で無効化され、設置・移動・回転・撤去のどれでも探索結果が新しく探索し直した結果と一致（`test_path_cache_follows_layout_changes`）。 |
| (2) 表示の補間が角を切る | **実在・主因** | 下表。修正前は x1 でも描画位置が棚の足元へ入った（4141件）。 |
| (3) 描画順の誤り | 問題なし | `DrawOrder` の制約を `compose()` の出力順が全フレームで満たした（検査 約5万件、違反 0）。 |

### (2) の仕組み

- シミュレーションは 60 ゲーム秒/実秒で進み（1 ステップ = 2 ゲーム秒）、客は 0.6 タイル/ゲーム秒で歩く。1 ステップで約 1.2 タイル進む。1 フレーム (1/60 実秒) では x1 が 1 ゲーム秒（約 0.6 タイル）、x2 が 1 ステップ（約 1.2 タイル）、x4 が 2 ステップ（約 2.4 タイル）進む。
- 旧 `FixturePresenter._sync_customers` は表示位置を「最新の目標（現タイル＋次タイル方向の進み）」へ指数スムージングし、2.5 タイル以上離れると目標へ瞬間移動していた。
- 表示が追いつかないと 2.5 タイルの瞬間移動が起きる（検証で x1 でも最大 3.43 タイル/フレーム）。その直線が折れ角を横切り、棚のセルに入った（x1 で 4141 件）。フレーム間の直線も角を切った（x2 で 2263 件、x4 で 959 件、最大 4.41 タイル/フレーム）。

## 試験の内容

`tests/scenario/test_customer_paths.gd`:

- 店舗: 1×2 棚（通常）、回転した 1×2 棚（rot 1/2/3）、回転した 1×2 冷蔵ケース、2×2 冷凍庫、レジ（16×12）。配置と補充は `GameCommands`（検証付き）で行う。
- 各ステップ（論理）: (a) 客が立つタイル・残り経路が什器の占有セルでない、(b) 移動は 4 近傍（隣接タイルのみ、角の斜め移動なし）、(d) 棚へ向かう客の目的地は、その什器の正面アクセスタイル（`PlacementRules.access_candidates`）で、購入（レジ待ちへの遷移）時の位置も同じ。
- 各フレーム（表示、速度 x1/x2/x4、フレーム 1/60 s × 速度）: `FixturePresenter._sync_customers` に実際のスナップショットを渡す。(c) 描画位置、および前フレームから今フレームまでの線分が、什器の占有セルから半径 0.2 タイル以内に入らない。(e) `compose()` の描画順が `DrawOrder.is_behind` の両方向の制約を満たす。
- 経路キャッシュ試験: 棚を経路上に置く → 経路をまたいで移動 → 回転 → 撤去のたびに、`CustomerAI._path` の結果が毎回 `PathService.find_path` の新規探索と一致する。

## 結果

| 検査 | 修正前 (HEAD) x1 / x2 / x4 | 修正後 x1 / x2 / x4 |
|---|---|---|
| (c) 描画位置・線分が什器に入る違反 | 4141 / 2263 / 959 | **0 / 0 / 0** |
| 1 フレームの最大移動（タイル） | 3.43 / 3.43 / 4.41 | 1.21 / 2.55 / 7.00 |
| (a)(b)(d) 論理違反 | 0 / 0 / 0 | 0 / 0 / 0 |
| (e) 描画順違反 | 0 / 0 / 0 | 0 / 0 / 0 |
| 購入 / 選択 / 移動（試験内） | 71 / 168 / 5956 | 71 / 168 / 5956 |

- 修正前の試験は 399 件中 3 件失敗（3 速度の (c)）。修正後は 399 件すべて成功（failures=0）。
- x4 の最大 7.0 タイルは、直線の区間を 1 フレームで追いつく動き。直線の上を進むので什器も角も横切らない。角では 1 フレーム止まるため、x4 の見た目の速度は近似（後述）。

## 修正内容

1. **`scripts/presentation/fixture_presenter.gd`（主修正）**: 表示位置は、客が実際に歩いたタイル列（`trail`）と残り経路（`path`）の上でだけ動く。指数スムージングは「遅れの追いつき」だけに使う（`SHOW_EASE` = 120）。順方向の移動は次の折れ角（`_next_turn`）で止まり、フレーム間の直線が角を切らない。トラックに無い瞬間移動（出現・テレポート）は再配置とする。
2. **`scripts/application/customer_ai.gd`**: `_walk` が歩いたタイルを `trail`（直近 32）と `moved` に記録する。表示用の記録だけで、シミュレーションの判断は読まない。ゴールデン値は変わらない（試験 399 件が通過）。
3. **`scripts/application/game_state.gd`**: スナップショットの客に `path` / `trail` / `moved` / `fixture_id` を追加（表示と観察用。セーブには入らない）。
4. **`tests/scene/test_customer_sprites.gd`**: 旧「指数イーズ」の期待（2.0〜2.6 の間）を「経路上を進み、次のタイルを超えない」に変更。意味が変わった箇所のみ。

**変えなかったもの**: 経路探索（BFS）、アクセスタイルの計算、経路キャッシュ、描画順、シミュレーションのゴールデン値。いずれも検証で正しいと確認した。

## 残課題・注意

- **レイアウト変更中の経路再計算は未実装**。建設は SETUP（客 0 人）でのみ可能なので、現仕様では棚が客の経路に新しく入ることはない。仕様が変わって営業中に建設できるようになる場合は、`CustomerAI` で残り経路の再検証が必要。
- **x4 の見た目**: 角では表示が 1 フレーム止まるため、x4 では客の遅れが少しずつ増えて直線で取り戻す。角を切らないことを優先した結果で、速度は近似。
- **棚の回転スプライトの向き**は未確認。論理の正面（`access_edges` を回転したもの）と、スプライトの正面が一致するかは目視で見る必要がある。オーバーレイの黄色いアクセスタイルとスプライトの正面を比べれば判断できる。今回の試験は論理側（アクセスタイルの位置）までを保証する。
- 検証の実行方法: `godot --headless --path . --script res://tests/run_all.gd`（全体 約 3 分）。
