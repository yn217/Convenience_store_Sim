# グラフィック品質改善 Phase A: 現状分析 (Issue #61)

更新: 2026-10-24。対象: 統合ブランチ `integration/m6-ui` (PR #81) と main(Codex #62/#65/#66/#67 取り込み済み)。

## 1. 描画の構造(実装側)
- 什器: `FixturePresenter` が列セグメントごとに shadow/body/商品/glass_front を描く。描画順は `DrawOrder`、描画コマンドはセグメント単位でキャッシュ。
- 商品: ズーム0.9以上でコード生成の `ProductIcons`(自作の仮形状)、それ未満は色付き四角。SKU→スロットは snapshot の `shelf_skus`。
- 床・壁・光: 床は単色チェッカー、壁は `WallLayer`(コード描画)、光は `LightGlow`、看板は `SignLayer`。
- GUI: 左ナビ/右カード/コマンドグリッド/指標カードは実装済みだがアイコンなし・サムネイルなし。

## 2. 素材側(Codex)
- 什器スプライト: 10種×4方向。私のBlenderパイプラインとほぼ同じ見た目(白い箱に棚板)。**素材品質の限界は、モデルが単純なプリミティブの組み合わせであること**。
- 商品: `assets/generated/products/` に8形状×4方向(256px)と24SKUのマッピング(`products_manifest.json`)。カテゴリ名の帯がついた平坦な簡易形状で、パッケージ画ではない。Godotからは未使用。
- AI生成のパッケージ候補(おにぎり/お茶/カップ麺 各2案)と切り抜き・256px・LOD(0.25/0.5)。**採用前**(商標/文字レビュー・出典未確定)。
- 什器の材質候補(金属棚/木目棚、冷蔵ケース、レジ)と POP 候補。ゲームには未接続。
- mainとの重複: 什器スプライトは両レーンが別々に生成しており、main と integration で add/add 競合する(見た目はほぼ同一)。

## 3. 品質が低く見える原因
|原因|種別|対策|
|---|---|---|
|什器が白い直方体+棚板|素材(モデリング)|Blenderモデルに材質・化粧板・ハンドル・サイン面・足元を追加(基準3種から)|
|商品が小さな四角/単純形状の繰り返し|実装+素材|既存のCodex商品形状と切り抜きの接続、SKUごとの色・向き・個体差、在庫段階表現|
|床・壁が単調|実装|床タイルのテクスチャ(手続き)、壁の質感、接地影|
|ガラス・光の表現が弱い|実装|ガラス反射/ハイライト、什器の接地影、照明の統一|
|GUIにアイコン・サムネイルがない|実装|SVGアイコン、建設パレットのサムネイル、パネル幅/開閉|
|店舗中央領域が狭い|実装|パネル幅・開閉の見直し|

## 4. 実装順(Issue #61 に反映)
A 分析(本書) → B 基準3種(レジ/汎用棚/飲料冷蔵)のモデル品質+商品接続 → C 床・壁・光 → D 残り7種へ展開 → E GUI仕上げ。各段階で同一条件の Before/After スクリーンショットとベンチを残す。

## 5. Codexへの素材要求(画像生成が必要なもの)
- 24SKU分のパッケージ表面(おにぎり/ペットボトル/カップ麺/パン/お菓子/デザート/おでん/アイス): 透過PNG、256px正面、LOD 0.5/0.25、架空ブランドのみ、文字は可読な日本語の短い名称。
- 床材(タイル/ビニル)と壁材のタイル可能テクスチャ: 512px、継ぎ目なし、PBR不要。
- 什器の材質差し替え(金属棚/木目棚/冷蔵ケースのガラス扉の反射マスク)。
- 看板・POP: カテゴリ別(おにぎり/飲料/アイス/おでん/デザート/パン/カップ麺/お菓子)の透過PNG。
合格条件: 透過端がきれい、商標なし、`docs/ASSET_CREDITS.md` に出典、`tools/validation` を通ること。
