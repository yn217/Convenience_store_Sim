# 2.5D アセット制作・描画仕様 v0.1
更新: 2026-10-22｜対象: Blender生成アセット、Godot 4 Sprite2D描画、商品ラベル

## A. 画風と前提
- **固定視点・リアル寄りの日本のコンビニ**。金属、ガラス、プラスチック、食品包装、冷蔵照明が伝わるスタイル。架空ブランドのみ。
- 「2.5Dアイソメトリック」は**2:1菱形グリッドのゲーム用ディメトリック表現**を指す（厳密な等角投影とは区別）。実行時に3Dカメラを回さない。
- 元モデルはBlenderのメッシュとスクリプトを保持し、ゲームでは透明画像＋配置データ。AI生成は**小物・パッケージ/POPのテクスチャ**が主用途。
- レンダー/出力画像に床影を焼き付けるかは別レイヤーを基準に統一。影が隣の什器に二重重畳しないこと。

## B. 座標・投影・実寸規格
|項目|規約|
|---|---|
|論理グリッド|x=東、y=南、z=高さ（m）、右手/Blender座標との変換を生成スクリプトで明示|
|タイル実寸|1.0m×1.0m（MVP仮値、全アセット共通）|
|表示タイル|ズーム1.0で菱形128×64 screen px（幅:高さ=2:1）|
|位置式|tile (x,y) の基準点 = (origin_x+64(x-y), origin_y+32(x+y))|
|正投影|地面のX/Y軸が画面で±(64,32)px/タイルになるようBlenderカメラと正投影scaleを校正|
|カメラ|方位45°、仰角約30°を出発点にするが、**数値より投影した校正結果を正とする**|
|スプライト|4方位を原則必須（0/90/180/270）。エンジンが画像を無条件ミラーすることは禁止|
|解像度|基準表示の2倍で書き出す（菱形1タイル=256×128 source px相当）、エンジンで1/2スケール。PNG RGBA（α保持）。WebPは視覚検証後の最適化|
|初期対応表示|1920×1080、ズーム0.5〜2.0。商品識別は最小ズームではUI文字とカテゴリ表示へ委譲|

**座標例**：タイル中心の接地基準座標はタイル(0,0)の基準から(+64, +32)または(-64,+32)を繰り返し加算する。**接地アンカーはタイル中心でなく什器の論理占有の基準点に結びつく**。その基準点から投影された占有多角形とスプライトの足元接地点が一致しなければ採用しない。

### B.1 回転
- 向きはローカルNorthを0とする clockwise quarter-turn (r∈{0,1,2,3})（視点上の左右ではなく**店舗平面上**の方向）。
- w×hのセルにおける回転:
  - r0: (u,v)→(u,v)、サイズ(w,h)
  - r1: (u,v)→(h−1−v,u)、サイズ(h,w)
  - r2: (u,v)→(w−1−u,h−1−v)、サイズ(w,h)
  - r3: (u,v)→(v,w−1−u)、サイズ(h,w)
- front/access_sideも同じ回転を適用。N→E→S→W。**ルールによって画像だけ回し、アクセス面を回し忘れることは禁止**。
- 新方向の画像は、回転後の占有矩形を基準に元モデルをレンダリングし、各方向ごとに同じ規則でanchorを計算。

## C. 什器アセットの単位
- FixtureDef: fixture_type_id / display_name / footprint(w,h) / height_m / price / access_edges / shelf_slots / capacity / visual_def_id。
- **VisualDefはロジックから分離**: body_sprite[rotation], shadow_sprite[rotation], door_or_glass_overlay[rotation] (optional), products_layer_anchors[rotation][slot_id]、contact_anchor_px、footprint_polygon_px、selection_polygon_px、draw_sort_anchor_px。
- 同じ店舗に複数のインスタンスを置くため、固定IDとinstance_idは別にする。
- **大きな什器の1枚絵で手前の人と奥の人の両方を正しく重ねられない場合**は、前景/背景に分割するか、描画セグメントに分ける。単純なYソートだけで済ませない。
- ガラス扉の前後順序は **背面・内部商品 → 透明扉 → 前面反射/ハイライト**を基本にして目視検証。
- 背の高い壁面棚で後方が見えないとき、選択した什器/客の輪郭または局所フェードを表示する。

## D. 商品と在庫の表現
**最大の原則: 什器本体の絵に商品を固定焼き込みしない。**
1. 什器本体（空の棚/冷蔵ケース）を描画する。
2. 棚スロットごとに商品形状（おにぎり三角/飲料筒/カップ麺台形等）のスプライトと架空ラベルを合成。各スロットの中心はローカル3Dで定義、各向きに2Dへ投影してmanifestで指定。
3. 在庫のロット・数量を**見た目用の描画数量へ丸める**。例: empty=0、low=1〜25%、medium=26〜74%、full=75〜100%。割合は表示だけで、ゲーム内在庫/売上は正確な整数。
4. SKUごとのシルエット差は定義できるが、同じ1SKUについて見た目の容器1個=実在庫1個としなくてよい。正確な数量はインスペクタに表示。
5. LOD: 遠景=カテゴリ識別、通常=形状＋色分け、近景=架空パッケージ。距離に応じた切替にヒステリシスを設け、ズーム境界のちらつきを防止。
6. 商品変更/棚補充/会計成立/廃棄後、表示に使う derived stock visual state を更新。セーブにはderived画像状態を重複保存しない。
7. SKU数×棚数×回転数の全組合せを**事前レンダリングしない**。組合せ爆発を防ぐ。

### D.1 透過画像・アンカー・マニフェスト例
```json
{
  "manifest_version": 1,
  "visual_id": "fridge_drink_a",
  "fixture_type_id": "fridge_drink",
  "footprint": {"w": 1, "h": 2},
  "source_pixels_per_tile_diamond": {"w": 256, "h": 128},
  "rotations": {
    "0": {
      "body": "fridge_drink_0.png",
      "shadow": "fridge_drink_shadow_0.png",
      "anchor_px": [128, 376],
      "sorting_anchor_px": [128, 376],
      "canvas_px": [400, 440],
      "slot_anchors_px": {"row0_col0": [147, 175]}
    }
  }
}
```
上記は**形式の例**であり pixel 値は確定値ではない。各向きの画像の接地pointとfootprint輪郭を校正して機械判定する。ディレクトリ外参照と未知の回転キーを拒否する。

## E. 制作ツール構成/ディレクトリ案
```text
assets/source/blender/fixtures/       # .blend / Blender Python generator
assets/source/textures/packages/     # AI/手描き架空パッケージ源データ
assets/generated/fixtures/<id>/      # PNG + manifest、バージョン管理方針は容量で判断
assets/generated/products/<id>/      # LOD商品スプライト
tools/assets/render_fixtures.py      # バッチ生成
tools/assets/validate_manifests.py   # anchor/footprint/4方位/画像寸法を検査
docs/ASSET_CREDITS.md                # 素材ライセンス・生成手法/出典
```
ゲームロジックのfixture_type_idは画像パスを直接知らず、visual_idからマニフェスト解決する。外部素材の再配布権が不明なものは採用しない。

## F. 基準3種と全10種の受入基準
- **先にレジ/汎用棚/飲料冷蔵ケース（各4方向）**を完成。1×2の回転時の接地ズレ、冷蔵庫の扉/商品の重なり、棚の奥側に立つ客の重なりを比較。
- 1×1の小型おでんと2×2のアイスケースを追加してサイズ違いを確認。
- 表示画像は同じタイル座標、アンカー、光源を共有。定義と見た目が異なるアセットはリリースしない。
- 自動検査: 4方向存在、PNG alpha、画像サイズ/anchorがキャンバス内、slot anchorが妥当、画像パス存在、商品レンダリングLOD。
- 目視検査: 複数什器の隣接、透明ガラス、客が手前/奥に通る、棚商品が売れて減る、画面拡大縮小、プレースホルダー切替。
- 初期10種は GAME_DESIGN_SPEC.md の設備マスタが正。容量・寸法はバランス調整可能だがスキーマなしで変更しない。
